**1．UAV真正知道什么？**

每经过一个位置，记录一条`位置、时间、总干扰功率`。例如一串读数逐渐变大，说明沿这段实际航迹遇到的干扰在增强。dBm只是功率的对数表示，−70dBm比−80dBm强10倍；负数不代表负功率。

系统保存完整历史；GP按自己的近期窗口更新；各等效场解释也用新读数更新证据。不能据此知道源在左边还是右边，位置变化与源随时间变化也可能混淆。建筑几何和自定位是已有条件，不是从功率读数反演出来的。

**2．现在的“等效源”是什么？**

当前不是在真实传播模型中寻找发射机，而是用几个平滑“干扰团”组成一幅假想功率分布。每团有中心、尺度、移动速度、变强/变弱速率和强度。中心附近贡献大，远处逐渐衰减，没有硬性的影响圆边界；尺度不是传感半径，也不是禁飞半径。

同一个解释中的干扰团在线性功率域相加，再转为dBm。代码另加固定−100dBm背景。不能直接把多个dBm数值相加。真实仿真场仍用传播代码计算反射/穿楼等；高斯干扰团只是推断代理，不要求中心和真实源重合，也没有把建筑传播机制直接嵌入这个代理。

因此，真正期望的“等效”是：虽然源的位置和数量可以不对，但对任务相关位置/未来时刻的功率变化、路线暴露和路线优劣能给出有用近似。**当前拟合目标只约束历史读数，尚未保证这种任务等效。**

代码：[equivalent_field.py](../src/uav_em/equivalent_field.py)。

**3．系统怎样提出这些干扰团？**

目前使用有限字典，不是自由位置优化，也不是神经网络：

| 可选内容 | 当前实际取值 |
|---|---|
| 机制 | 静止、匀速平移、强度随时间变化，三类分别拟合 |
| 中心 | 相对拟合锚点按80m间隔列候选，保留160m内且在地图内的位置 |
| 尺度 | 40、80、160m |
| 平移速度 | 东/西/南/北四个方向，各3m/s；不是任意速度 |
| 强度变化 | 每秒−0.5或+0.5dB；不是任意变化曲线 |
| 作业区域 | 整个任务圆盘，或相对朝向goal的左半/右半 |
| 每个解释的容量 | 作业选择最多1或2团；不是整个池最多2团 |

这些是计算原型的搜索取值，不是论文标定的设备参数。位置160m限制的是新干扰团中心候选，场函数仍可被查询到更远处，但远处预测没有因此得到证据保证。pilot的锚点是截去最近3条后剩余历史的最后位置；refine锚点是当前位置。并非任意把真实源附近作为搜索中心。

旧的同机制高权重解释若传播到拟合时刻后仍落在允许区域，可提供热启动。不是每次都完全从零开始，但也没有实现任意基元合并、自由连续移动、进化搜索或可学习源提议器。

代码：[event_inference.py](../src/uav_em/event_inference.py)，`operator_dictionary/in_region/fit_job`。

**4．怎样从字典里选出一个解释？**

一次拟合作业最多取最近12条可用历史读数。先看现有预测在哪些点偏低，再寻找哪个候选干扰团最能解释这些残差；这是归一化相关性引导的贪心选基元，并非穷举所有源组合。

选中一团后，数值最小二乘调整它的强度，让这些历史位置的预测功率接近读数；允许两团时再选择下一团，并联合调整已选各团的强度。**连续优化的是强度，中心、尺度、速度、变化率来自有限字典，当前不会由优化器自由调整。** 已有热启动可以先联合修正。

目标是历史dBm均方误差，不是定位误差，不是路线代价。强度限定在−140dBm到该拟合窗口最大读数+6dB；每次小求解最多40次残差调用，且仅接受数值成功、强度合法、拟合误差没有增加的结果。这些界限是数值约定，不是真源功率上界或电磁安全条件。

输出包括干扰团参数、拟合窗口、拟合误差、求解过程和预算消耗。拟合很好只能说明“解释了这些已见点”，不能推出“其他位置也对”。

**5．LLM现在能参与哪一步？**

推断接口允许LLM输出一个受限作业计划，例如：

```json
{
  "request_id": "当前请求的ID",
  "stage": "inference",
  "jobs": [{"family": "translate", "region": "left_half", "max_bases": 2}],
  "reason": "检验左侧移动干扰的解释"
}
```

这是一个pilot阶段输出示意，不是实际模型回复。LLM选择“先检验哪类解释、哪个区域、多少团”；数值工具决定具体选哪些字典元素、强度是多少。LLM目前不能自由输出一个源就直接让系统信任，也不能修改证据权重。

一次事件有两轮：

1. **pilot：**组织1个作业，拟合时不使用最近3条读数；用拟合结果预测这3条，返回偏差和误差。该尾段已在请求历史中可见，因此是回顾诊断，不能称独立盲测。
2. **refine：**结合刚才反馈再组织2个作业，使用当前历史窗口拟合。每事件至多3个解释、6次小求解、240次残差调用。非空解释随后一起加入池。

当前推断请求含历史读数、已有解释与证据、机制表现、目标/地图边界、工具额度和pilot反馈；**尚未把GP样本、完整建筑几何和剩余路线直接加入推断请求**。路径请求另外有几何、GP局部样本、资源和候选路线。

不传`inference_advisor`时，由数值feedback规则组织：参考各机制最近预测证据，先试一类，再依据pilot尾段残差安排后两类。旧C1实际飞行用的就是数值组织推断，LLM仅参与路径。之前另有真实LLM组织推断的小试验，但没有证明预测改善；不能把接口存在写成已证优。

代码：[event_llm_inference.py](../src/uav_em/event_llm_inference.py)。

**6．为什么要保留多个解释，怎样判断更可信？**

沿一条短航迹读到相同的功率变化，可能由左源、右源、远处强源或近处弱源产生，不能强行选唯一真相。当前是平坦假设池，不是树。

初始化有两个保底解释：都把最近读数延续到其他位置/未来时刻，但标准差分别为4和12dB；第二个是宽残差解释，不是另一张已推测出的源地图。每次加入新解释，把原池总权重乘0.75，新解释均分0.25。这是声明的出生先验，不是学习出的真实概率。

之后每到一个新位置，先用旧解释预测该位置/时刻，再读取点测，按高斯观测似然更新各解释权重。预测接近新读数的解释通常更受支持，但不确定性大小也影响似然。新生解释从出生后的点测开始累计证据，不回头用拟合历史给自己加分。旧解释继续保留，不在每点重拟合；当前也没有独立的长期淘汰/合并机制。

重要区别：同一解释内的两团可以相加；“仅左侧有干扰”和“仅右侧有干扰”是两个互斥解释，规划时分别计算再加权，不能叠成“左右都存在”。

代码：[event_inference.py](../src/uav_em/event_inference.py)，`HypothesisBank.issue/observe/birth`。

**7．这些解释怎样真正影响航迹？**

候选路径上每段都有预计到达时刻。系统分别问每个解释：“UAV到这里时，功率大约多强？”然后沿路累计线性功率暴露，与航时一起评分，最后按证据权重混合各解释的路线分数。

路径目标仍为`C = T + Q`：航时加归一化干扰暴露；−80dBm是暴露代价单位，不是必须躲开的阈值。当前由高斯dBm预测计算期望线性功率，标准差也会改变Q，并非只对均值地图积分。误差模型未校准，所以图上颜色淡也不保证路线分数低或真实安全。

先保留当前剩余路线、直达及少量固定方向中间点作为简单候选；LLM可另提一个中间点及采样额度。工具能直连就直连，受建筑阻挡才调用有预算RRT*；最终共同接受器检查几何、能量、全程航程上限，并按同一预测目标选择。只改尚未飞过的路线。

执行短段后再点测，这条新读数又反过来检验解释，形成“观测—解释—路径—新观测”的闭环。不能仅以预测分数变小就称有效，仍要看冻结飞行后的真实暴露和航程。

**当前GP与等效场还不是内外区域融合。** `mixture`评分使用假设池，`gp`评分走独立GP接口，路径LLM可同时看到少量GP局部信息。不能把右图GP当作等效场实际规划地图，也不能说GP已在内区校正了等效场。

代码：[scenario_planning.py](../src/uav_em/scenario_planning.py)、[feasible_scenario.py](../src/uav_em/feasible_scenario.py)、[scenario_loop.py](../src/uav_em/scenario_loop.py)。

动画右侧底图是GP，紫叉只是最近一次决策top3解释的部分基元中心，并非一张确定等效地图。不同解释的叉不能理解为同时存在的所有源；8秒之后的紫叉也不都已获得未来证据。新回放要把这个语义显示清楚。

一个结构性难点：对于沿直线采集的读数，径向高斯团位于航迹上方或镜像下方，可能产生完全相同的历史预测；移动团的中心/速度一起镜像也可能如此。在没有新侧向证据或有效额外先验时，更强LLM也不能唯一判别上下。它可以提出两种解释并选择检验过程，不能把偏好的解释当新测量。实际转弯后的读数才可能逐步区分；时间变化仍可能混淆这一判断。

据此，后续方法应让LLM优化**解释构造与检验过程**，而非直接输出可信源坐标：

- 先用现有机制/区域/容量接口接真实事件闭环，让推断LLM依据历史点测、已有解释及工具残差决定先检验哪类解释；工具返回数值结果，再交给路径LLM。保持简单规划并生成实际replay，不先实现下面所有增强。
- 对有歧义的方向保留成对解释。镜像候选应是替代世界，不是在一张地图里同时增加上下两个源；先用现有左右区域作业表达，必要时再增加显式镜像算子。
- 若回放显示粗字典不够，再给数值工具增加有界局部细化，使中心、尺度或速度可在粗候选附近修正；LLM选择细化对象与预算，不凭语言生成精确数值。该算子尚未实现，必须另定有限求解额度。
- 若新读数持续高于所有已发预测，考虑“旧解释继续传播＋新增干扰团”，同时保留移动/强度变化等替代原因。不能把每次失配都断言为新源，也不能把新团自由叠加到所有互斥解释；事件式增量结构尚需实现和验证。
- 显示每个解释的出生后证据、近期预测偏差以及对各路线Q的贡献，区分“源解释方向错”和“解释虽有方向信号但在共同目标中作用弱”。初期不改既有权重和目标来强行制造避让；若要改证据/非平稳更新，按独立假设验证。

第一目标是允许适量暴露下更稳定地脱离/避让干扰并到达goal，不要求绝对零暴露或真源定位；随后再加强航程优化。现有航程、能量约束和T+Q保持，不能为好看而静默换目标或拿失败航迹的短积分当成功。

文献对应仍是工具组织/反馈推理（Code as Policies、ReAct、Inner Monologue）与任务相关表示（task-based learning）；attention/仿真摊销提议器保留为后续增强，不以训练网络替代最近的可观察闭环。上述是有缓存依据的改进设计，不是新算子已实现或收益已验证。
