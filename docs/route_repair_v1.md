# 第一版：区段修复、采样分配与数值反馈

更新：2026-11-10。本文描述已落地的第一版接口及已完成的集成验证；研究创新是否成立仍需受控实验。试验入口为`outputs/interference_route_repair_20261110/index.html`。

## 决策流程

固定当前点测与局部时空GP，在一个决策点内不推进飞行、不增加观测、不修改估计器。对剩余路线保留所有原拐点，长边以不超过80m的间距插入连接点，编号`a0,a1,…`。LLM看到每个区段的长度、干扰/不确定性代价、支持比例、支持年龄和近期真实点测，选择要修复的区间及操作。

区段选择没有唯一预设答案：读数升高且当前航段已有强干扰支持时，可以修复当前位置到风险段之后；远处主要未知时，应承认方向歧义，不能把某个走廊当作已测安全。已有侧绕过长、出现更好的观测后，可以试快捷连接或提前接回。数值策略可以用同样字段和操作，不把LLM设为唯一可用优化器。

`route_repair`中的路线是当前最佳路线。每次接受新候选递增`route_version`并重新给出连接点；旧id不能跨版本使用。修复外侧路线保留，整条拼接路线仍重新评分/复核。插入同一直线上的连接点不会改变J。

## 实际支持的操作

| operator | 输入 | 数值执行 |
|---|---|---|
| keep | 当前版本、简短依据 | 有可行旧路时结束本决策点优化，保留路线 |
| shortcut | start_id、end_id | 用直线替换指定区间，检查碰撞和完整候选代价 |
| local_rrt | 区间、sample_budget、sampling | 仅在选定端点之间建立新RRT*，替换区间并保留两侧 |
| via | 上述字段加waypoint_m | 经一个中间点进行两次搜索，两腿共享该次请求的样本额度及总边额度 |
| global_rrt | sample_budget、sampling | 从当前UAV位置到goal重新搜索，没有局部区间id |

第一版只复用路线，**没有持久化/修复旧搜索树**，不称为RRTX。原基础模式的`continue/replan/probe`仍可运行，但新修复模式目前不提供主动补测行动。GP模型选择、函数生成、局部代码执行及训练不在这一版实现中。

## RRT*如何扩展

`repair_search.py`在标准选父、重接和后代代价更新之外加入采样器与共享资源计数。采样混合为：

```text
p(sample) = 0.10 * target_endpoint
          + p_focus * weighted_uniform_boxes
          + (0.90 - p_focus) * uniform_whole_map
0 <= p_focus <= 0.60
```

LLM最多给3个边界内矩形，各自权重只决定focus分量内的相对采样概率；至少30%保持全域均匀。局部修复的target_endpoint是所选区间末端，不一定是最终goal。即使是局部连接，树仍可在全图搜索；“局部”指替换的路线范围，不是硬限制树活动的空间范围。

第一版通过提高其他区域的采样比例间接减少可疑区域的搜索占比，没有硬排除盒。采样点落在低风险区域并不阻止连边经过强干扰，所有父边、重接边及终点连接均使用同一个固定J与几何检查。没有增加LLM自定的风险权重，也没有由模型删除可行域。保留全域采样不等于本实现已证明渐近最优/有限预算必达。

## 固定评价目标与候选接受

```text
J_t(route) = integral_route [1
    + 2.0 * clip((GP_mean_t(x) - reference_dBm)/10, 0, 4)
    + 0.4 * clip(GP_std_t(x)/15, 0, 2)] ds
```

固定权重1/2/0.4、参考值来自任务配置；模型不能通过profile修改。沿最近邻栅格半格边界精确分段积分，避免端点采样均值随直线拆段方式改变。`ds`单位m，J是研究性估计代价，不是未来真实暴露。未知格数值计算使用背景先验及未知不确定性，公开读数仍为null；不因为需要评价就把它说成安全。

整条候选须保持当前位置/goal端点、建筑净空及能量可行，并满足`J_candidate < J_best - 1e-7`才接受。失败或无改进保留旧路。反馈包含候选和当前最佳的长度/干扰/不确定性分项、差值、失败原因及剩余资源。每个决策点最多3轮；下一轮根据反馈修订区间、操作或采样额度。新观测到来后重新评分旧路线，**不声称跨快照单调改进**。

当前能量复核计一次决策的固定悬停及整条飞行路线；没有预测未来所有决策的悬停、动力学或实际推理延迟。允许软代价暴露，不是硬安全保证。

## 预算与记账

| 设置 | 第一版默认 | 说明 |
|---|---:|---|
| max_rounds | 3 | 每决策最多咨询轮数，整数1–3；任务模型调用上限另限制 |
| sample_limit | 2100 | 每决策所有搜索/轮次/恢复共享的采样提议上限 |
| edge_limit | 10000 | 每决策未缓存的几何/边代价计算及最终几何复核总上限 |
| anchor_spacing_m | 80m | 连接点最大间距，保留原拐点；不是感知范围 |

每次`sample_budget`是从本决策剩余额度中申请的上限，不补充总预算。via在两腿间拆分请求额度，失败不自动把额度重新分配。边预算可能先耗尽，此时若已有可验证的解可返回已有解。搜索预留少量候选评分/终检资源，接受旧路时保留其终检额度，避免把最后一次边计算用完后无法复核。对称边缓存仅在当前快照/决策内共享；缓存命中单列，最终几何终检实际执行并计数。

初始无可行路线或模型错误后，数值恢复只能使用剩余额度；可行旧路存在时可以保留，不做无预算的额外全局重搜。初始化评分、候选评分与终检计入边台账。公共上下文构建、场采样摘要、GP、真实执行碰撞检查不是该规划边台账，另由墙钟体现；不能把相同计数上限说成相同CPU耗时。

任务调用预算耗尽后不再冒充模型响应：已有可行路线可保留，无路线时的剩余预算数值恢复单列。本轮没有引入学习门控或按实际计算时间飞行。

## JSON示例

以下仅说明格式，不是实际模型输出，也不表示区域已知安全：

```json
{
  "route_version": 2,
  "operator": "local_rrt",
  "start_id": "a1",
  "end_id": "a5",
  "sample_budget": 250,
  "sampling": {
    "focus_probability": 0.6,
    "regions": [{"low_m": [160, 80], "high_m": [500, 240], "weight": 1.0}]
  },
  "reason": "尝试侧绕已获支持的高代价区间，未测区域仍需后续观测"
}
```

外部响应封装沿用`request_id/decision/strategy/memory`，其中decision装上述提议、strategy固定baseline。版本、id、数值范围、未知字段与重复键严格校验；拒绝的原始响应仍保留，不自动修补成成功。

## 代码与验证

- `src/uav_em/repair_search.py`：固定目标积分、共享预算及RRT*采样扩展。
- `src/uav_em/route_repair.py`：区段、协议、有限轮反馈、接受器、数值对照及文件LLM策略。
- `src/uav_em/simulation.py`：可选`route_optimizer`接入原点测/飞行闭环，阻止旧求解路径绕开预算。
- `tools/run_repair_study.py`：冻结新场景、分别运行数值/独立单轮LLM/独立多轮LLM、生成报告与GIF。

实验中每个LLM方法使用新独立会话，只读其public子目录。给出近期点测、固定GP、已知几何和求解反馈；新模式不发送旧`source_inference`字段。共享文件系统的allowlist不是OS隔离。

需要验证的是反馈是否改善有限搜索分配，以及是否改善真实闭环航程/暴露；仅J不增是接受器设计带来的性质，不能独立证明LLM有贡献。当前数值策略是简单开发对照，后续仍须补充分配更强的数值自适应对照、多场景/多种子及区段/采样/反馈消融。

## 2026-11-10集成试验结果

[报告](../outputs/interference_route_repair_20261110/index.html)、[3个GIF](../outputs/interference_route_repair_20261110/replay/index.html)。一个预先固定动态场景，每个方法一个种子；使用两个新独立LLM会话。

| 方法 | 到达 | 航程/m | 飞行超参考积分/dB·s | 总样本 | 总边评价 | LLM调用 |
|---|---|---:|---:|---:|---:|---:|
| 简单数值操作选择 | 是 | 720.00 | 175.940 | 7753 | 69149 | 0 |
| 单轮LLM | 是 | 720.21 | 181.928 | 1111 | 29697 | 7 |
| 最多三轮反馈LLM | 是 | 720.00 | 175.940 | 780 | 17442 | 11 |

18次真实模型响应均无错误，无数值恢复；预算与因果接口审计通过。多轮LLM在初始搜索后用shortcut降低当前J约2.81，后来局部搜索无改进时停止；一次via反馈增加J约22.89被拒绝，再选择保留旧路。区间/采样/反馈/拒绝均实际执行，但这次所有方法主要保留直达路线，**没有验证干扰规避提升**。

多轮LLM的路线和真实指标与简单数值策略相同，边评价约少74.8%；数值策略反复全局重搜，仍是弱开发对照。简单数值的提前停止/改进上界规则可能复现节省，因此不能据此声称LLM效率创新成立，更不能用较少传统搜索忽略模型调用成本。

下一步应先诊断为何局部GP当前目标下侧绕没有改进：区分候选搜索失败、估计支持范围不足、未知惩罚及当前快照目标的短视性，再设计强数值自适应/提前停止对照和区段/采样/反馈消融。不得为让本例更好看而调整冻结目标或给模型真值。主动补测和到达时刻预测仍是明确未接入能力，需另行收敛实现范围。

该版收尾时373项测试通过。审查修正了完整修复耗时计账和超时报告的缺陷；冻结版`planner_seconds`仅含RRT搜索，历史遗漏时间不补造、不用于总时延比较。三方法在当时修正源码上重放已保存提议，轨迹/主要指标/资源计数一致；这不是新模型调用。冻结版本与修正版本哈希分开记录，见reports/audit.json和reports/reproduction.json。最新预设算子程序及当前测试状态见[程序比较](program_comparison.md)，不冒充与本版旧哈希一致。
