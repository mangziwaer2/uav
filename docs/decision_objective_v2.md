# 共同决策目标v2：短段风险与全程绕行上限

更新：2026-11-11。此前开发诊断表明当前J可能拒绝低真实暴露的绕行。本轮先实现独立的**人工数值控制器**，检查共同目标是否可用；不调用LLM、不生成新算子、不改传播/GP/传感器或原v1接受器。实验前本文件与代码冻结到新研究，结果另行补充。4个开发城市已用于诊断，本轮属于开发集上的方法修改，不是未见验证。

## 固定设计与计算依据

1. **航程约束单独定义。** 首次决策在共同候选池中找最短可行路线，长度记D0（有限搜索参考，不是几何最优）。全任务允许飞行距离1.25D0，保留能量限制；以后必须满足`已经飞过+候选剩余≤1.25D0`。每次决策从实际执行反馈累计飞行距离，不按新路线反复乘1.25，不等待或声称硬干扰安全。初次若找不到路线，保留失败。
2. **近期风险用dB·s代理。** 沿候选接下来10s（速度15m/s时150m，至goal则提前结束）计算。10s与现有周期复核一致，观测事件仍可提前触发；这不是保证10s不会变化。已支持区域用当前GP的高斯假设`E[(X−reference)+]`积分，**不截断高干扰**。未知区域不用−100dBm背景均值作低干扰，而显式记未知秒数，并以每未知秒10dB的研究性厌恶系数计代价：`R10=已支持期望超参考积分+10×未知秒数`。10dB是既有归一化尺度对应的预声明偏好，非测量、上界或硬安全保证。GP不预测到达时场，不确定性未校准，以上只是当前证据下的排序代理。
3. **接受器固定。** 几何/端点/剩余能量/全程航程上限先过滤，再最小化R10。先找最小风险值，在其+1dB·s内选择最短剩余路线，同长保留原路线。1dB·s来自1dB测量噪声×1s测量步长的数值容差，是偏好而非置信检验；不使用顺序累积容差。尾段只报告支持/未知比例，不声称对完整未来暴露有可信预测。原J仍完整报告，但v2不要求J下降。
4. **动作不扩展。** 只返回到goal的完整可行折线，飞行中继续真实点测。侧绕不是免费补测，也未接主动probe；不从标量点测伪造测向。全程距离上限限制绕圈，但不能保证任务必成功或所有状态有修复空间。

## 共同候选与资源

两组人工数值方法：`pool_j`以原J接受；`prefix_v2`以上述R10接受。两组均使用新公共候选生成器，区别仅选择目标，不能用它们与历史library_numeric差值声称目标单独收益。

每决策同样构造：当前剩余路线、起终点直连、当前航路whole及前150/300m区段的弦、左右0.5/1/1.5倍80m支持尺度的中点/平行侧移，再运行一次700样本原J-RRT*。重复路线去重、碰撞/能量无效保留原因。没有合法初始路线时先用700样本RRT*引导，然后构造相同池；初始已搜索则不追加第二次搜索。只读当前估计和已知几何。两组共享相同代码与预算上限，但不同飞行会产生不同观测与池；不声称不同状态下候选相同。

每次总上限2100样本/10000边，初始引导、候选几何/旧J、搜索和最后独立验证均计数；v2沿线的风险数组计算另记数与墙钟，不冒充等CPU。搜索前预留后续候选评分/终检额度；没有路线则明确失败，不启动预算外恢复。搜索器仍是原RRT*，没有持久树或改变其最优性理论。新控制器通过已有route_optimizer接口挂载，报告明确自己的版本，不能把新目标标成v1固定J。

## 场景、比较与预声明门槛

从前一研究原样复制dev611/613/617/619，不生成新场景、不改源或采样噪声；种子保持原样。验证701/709及测试1601/1607/1609/1613/1619/1621继续不生成、不读取。运行两组共8个真实闭环，所有失败保留；不根据真值改参数重试。先冻结设计/源码/输入，再跑全部飞行与呈现。

主指标仍为真实飞行超参考dB·s、航程、到达及计算开销；原仿真悬停暴露未计，额外事后报告从episode决策位置/时刻复算的悬停暴露和飞行+决策悬停总积分（不回传控制器）。真实计算耗时不推进仿真，不宣称部署时延。

开发可用性门槛同时要求：两组8项均到达、所有预算与航程上限满足；v2跨4场景总飞行积分≤pool_j的90%，平均航程≤pool_j的125%；每场景积分不增加超过`max(1dB·s, pool_j积分×10%)`。无统计显著性或泛化保证。悬停计入后的总积分是否也下降另外报告，不隐藏飞行/悬停权衡。

若门槛失败，完整报告，区分代理偏差、短视/航程耗尽、候选不足等证据；不得事后筛掉低风险城市或调整系数。若通过，只说明人工共同目标/候选的开发可用性；下一步冻结接口再小预算LLM离线设计及公平在线组合，不能把数值收益算作LLM推理收益。

入口`tools/run_objective_v2.py`；输出新建`outputs/interference_objective_v2_20261111/`，GIF集中`replay/`。本轮不改旧研究冻结证据或启动补测、训练/RL、源定位、自由在线代码。

## 误判证据与下一步

运行后对已冻结的v2状态，分别评价v2选择和该状态池内旧J选择的**固定10s前段反事实**；不是从该状态实际执行旧J闭环，也不能将这个反事实等同另一条完整飞行。全部决策见`reports/selection_diagnostics.json`，脚本与数值积分误差也保留。

dev619在20s时最新点测为−85.24dBm，尚低于软参考。v2侧移路线R10=33.692，旧J直线路线R10=54.150，因此选侧移。但分解显示：已支持期望暴露是6.186 vs 3.917dB·s，v2本来更高；未知秒数2.751 vs 5.023，使未知代价主导了选择。事后两条固定10s路线真实积分为22.108 vs 14.934dB·s，代理排序反向。说明“减少未知”不能直接等同“减少真实暴露”。

26.5s时飞机测到−77.65dBm，已飞375m，总航程上限961.769m。池内20个候选因全程航程约束被拒绝，最后选择直连；随后实际执行区间的积分约33.06dB·s。被拒绝路线的真实暴露是否更低并未在此证明；这个事实只说明早期绕行使用了后续机动余量，不能单凭约束拒绝推断反事实一定更优。dev619区间重积分和原逐飞行步积分相差约0.141dB·s，来自中点分段不同，不作位级相同声明。

因此v2保留为**未通过稳定性门槛的开发控制器**，不升级为论文最终方法，也不在当前结果上继续扫未知系数/权重。下一步先把“有支持的风险证据、未知代价、剩余绕行额度”明确放入状态/反馈，设计并数值检查证据条件化的绕行额度分配过程：弱风险证据时避免仅为减少未知耗尽余量，出现实际风险证据时才比较针对性区段修复；必须与本轮即时最小R10及同操作集合的数值策略公平比较。该过程尚未实现，不添加源方向或无成本新读数。

这能把后续离线算子与在线LLM的待验证作用收拢到**有限机动余量下的证据条件化操作组合**。是否需要LLM、是否能优于数值分配仍由实验决定；先冻结数值过程和门槛，再做有限生成，不把当前数值目标带来的合计收益算作模型推理收益。

收尾核验：`reports/reconstructed_risks_and_tail_support.json`记录61个决策，仅从已收到点测重建估计器后复算选中风险，全部一致。候选尾段在控制记录内只存长度；支持/未知比例通过同一因果估计器在该附加报告中派生，并未作为免费新信息或回填控制器。`reports/evidence_verification.json`核验26个共有源码不变、4初态候选/搜索评分工作一致，以及8GIF/episode哈希和逐帧解码；终检用边数量随选中路线不同，不声称两组实际资源完全相等。
