# 直接数值与预设算子程序：实现和验证

更新：2026-11-10。用户本轮授权比较直接数值输出与短代码/算子组合。本版已实现有限短程序解释器并完成验证，见[实验报告](../outputs/interference_program_comparison_20261110/index.html)。不覆盖第一版修复或基础点测证据。

## GP输入、内部数组和公开信息

GP的训练输入是已经获得的点测记录`(x_m,y_m,time_seconds,power_dbm)`，不是一张已知电磁地图。当前按访问网格保留最近测量，再选35s内最近最多64点。查询位置是已知地图栅格；主配置41列×31行、间距20m。内部输出同形状的均值dBm、预测标准差dB、支持布尔值、最近支持年龄s等数组，按`[row,column]`索引。

只有距有效训练点不超过80m的位置对外公开估计；这是模型支持边界，不是传感器一次扫描的范围，也不只围绕当前位置。其余位置在数值计算中保留背景先验与未知标准差，对LLM的估计均值为`null`。均值不是实测真值，预测标准差也未校准。

当前LLM并不接收1271个完整栅格：公共JSON包含最多35个全图稀疏样本、最多9个当前位置附近样本（排除不可通行点）、区域与航段摘要、近期点测和时效/支持字段。数值规划器可以使用同一估计器的完整内部数组。新短程序数值算子仅使用LLM同样可见的公共字段，不额外访问内部完整场、真源或未来。

## 不能修改已经发生的飞行

每次执行`advance_route`删除已飞过的前缀，把剩余路线首点更新为当前位置。`RepairSession`仅为该剩余路线生成当前版本连接点，所有修复id必须来自它；旧版本和不存在的id被拒绝。历史点测可以保留作为证据，但其位置不是可任意修改的历史航段。

候选路线仍可能在未来绕回曾访问的位置；这是将来的真实飞行，增加的长度/能量需计入，不是把过去轨迹“改好”。当前起点到目标端点和整条拼接路线仍由固定接受器复核。

## 短程序表达什么

`src/uav_em/repair_program.py`包含研究者预先编写并验证的数值算子。LLM生成最多12条赋值语句，选择并组合这些算子。语法采用Python形式，实际用AST逐节点解释，不调用`eval/exec`，不接受导入、属性、索引、任意函数、循环或文件访问。本轮明确授权的是预设算子程序组合，不是在线生成任意Python实现。

例如以下是格式示例，不冒充实际响应：

```python
part = select_interval(metric="interference", padding=1)
boxes = corridors(part, side="both", scale="local")
dist = sampling(boxes, weighting="cost", concentration="focused")
decision = local_rrt(part, dist, quota(mode="balanced"))
```

程序依次计算剩余路线风险区段、侧向采样矩形、区域权重和搜索额度，最终生成与第一版完全同格式的一个提议。不是把手填坐标放进Python字面量；本版不接受浮点坐标字面量。数值搜索仍在原`RepairSession`中执行，没有额外隐藏搜索或新资源。最多3轮的反馈可以修订下一段程序，但无代码进化、群体搜索或生成程序自我训练。

本版没有通用程序内分支/循环：条件行为来自预设函数，如按观测排序或按无改进反馈停止。任意函数实现的生成/优化不属于本轮能力；若表达能力不足，须另立对照后扩展。

## 数值算子及启发式边界

| 算子 | 数值工作 | 限制 |
|---|---|---|
| `select_interval` | 按支持加权干扰密度、不确定性密度、折线多余长度或近端排序；按连接点数扩展区间 | 不是最优区段选择保证 |
| `corridors` / `waypoint` | 由区间方向的法向量、支持距离倍数和地图边界计算侧向区域/中间点 | 不从功率伪造测向，左右都只是几何搜索候选 |
| `sampling` | 用公开采样点的固定目标密度倒数计算区域权重；保留至少30%全图采样 | 稀疏摘要可能漏峰；未知用数值先验，不声称安全 |
| `quota` | 根据剩余样本/边、轮数和已发生搜索的边/样本比计算额度 | 启发式，不保证预算全部利用或最优分配 |
| `shortcut/local_rrt/via/global_rrt/keep` | 产生普通修复提议 | 搜索、碰撞、能量与目标接受仍在统一数值层 |
| `stop_if_no_gain` | 当前快照上最近RRT搜索无改进时保留旧路 | 可能过早停止，不能当作改进不可能的证明 |

代码把数值计算交给机器，可以做到可复算；它不保证公式正确、GP准确或路线更优。预设尺度、背景先验和分配规则是研究参数。完整公式、函数签名和限制已冻结在每个方法的公共合同中。

## 本轮比较设计

入口`tools/run_program_study.py`，同一研究只使用一个入口。顺序：

1. `prepare`新建目录、固定两个既有场景、源参数、两组合同、源码哈希和选择规则，不根据表现筛选。
2. `baseline`使用同库数值策略飞行，从每个场景首次不早于12s和30s的实际决策保存精确GP快照，共4个任务。快照来自实际点测历史，不是人工编造高干扰数组。
3. `direct_values`、`operator_program`各使用新独立决策会话，先处理相同4个快照，再各自闭环运行s02。每个任务同一初始观测、路线、目标、搜索种子与资源上限，最多3轮。后续接受的路线可以不同，闭环后续观测也会不同。
4. `report`保存原始模型输入/响应、程序逐步计算、解析提议、数值反馈、预算和配对核验；GIF集中于`replay/`。

三方法为同库数值策略、直接参数LLM、预设算子程序LLM。同库数值策略先尝试快捷连接，有已支持干扰且资源允许时局部搜索，按搜索反馈停止；属于开发对照，不称最强传统基线。两组模型使用同样的公开观测，合同都说明预设库；直接组不能执行这些数值工具，程序组通过记录的解释器执行。程序组只能选择库中预设度量、尺度和预算规则，直接组可以手填任意合法参数，参数表达范围也不完全相同。因此本轮比较两套具体接口，包含**数值工具辅助与参数化**的变化，不能把结果全部归因于“代码语言优于数字token”。

每决策仍为2100样本/10000边评价，跨轮/双腿/恢复共享；固定GP和J，模型不能改权重。程序输出错误与解析成功后无收益分开记账。初始无路时的数值恢复单列，不算模型贡献。公共摘要计算和程序计算耗时另外记录，相同边上限不是相同CPU耗时。

独立会话只读自身public目录中的合同、控制、请求及响应，不读场景、完整episode或其他方法；这是流程allowlist，不是OS隔离。程序解释器本身也不获得文件、真值或未来脚本接口。

## 研究判断

配对任务只检验当前估计目标、可行性、程序有效率和资源使用，不能证明真实暴露降低。闭环任务另报到达、航程、干扰暴露及调用/计算开销。先验证“程序计算能否形成有用提议”，再讨论证据条件化的求解过程组合是否值得成为候选贡献；可运行、少量成功或接受器的代价单调性都不等于论文创新成立。

本轮仍不做GP函数选择、主体微调/RL、主动补测扩展、通信中断、持久树或任意代码在线执行。

## 已完成的试验结果

4个同快照任务、每组一个独立强LLM会话，再做s02一个种子的闭环。两组各29次响应，共58次，无解析/程序/执行错误，无数值恢复；所有程序及中间参数独立重算一致。当前392项测试通过，冻结源码/配对输入/预算审计通过。[真实程序与计算示例](../outputs/interference_program_comparison_20261110/reports/example_program.md)、[参数复算](../outputs/interference_program_comparison_20261110/reports/parameter_reproduction.json)、[4个GIF](../outputs/interference_program_comparison_20261110/replay/index.html)。

程序与直接参数接近，未优于直接参数；相对数值组航程更短、暴露秒数更少，但积分反而更高，且传统搜索和模型调用开销更大。没有验证更好的强干扰规避。飞行任务咨询墙钟合计约直接933s、程序834s（含文件桥接等待，程序计算另留逐步计时），仿真不按该耗时推进飞行，不宣称实时部署或总体效率优势。

结论是程序接口可运行、数值可复算，当前样本不足以决定全面替换直接参数。后续候选应考察证据如何改变修复范围、算子顺序和预算，并区分搜索不足与当前快照目标/估计支持的限制。当前程序组合的是参数生成过程，尚无程序内条件搜索序列；若扩展此类过程，需同库数值对照和额外受控实验，不把计划写成已实现。
