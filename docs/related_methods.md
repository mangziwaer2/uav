# 最接近方法的全文方法段对比

更新：2026-11-10。这是候选研究定位，不是穷尽综述或新颖性证明。本轮下载arXiv HTML全文，实际审阅下述方法段；没有声称逐页复现全部论文。下载URL、原文SHA256、文本和所读段落保存在[本轮文献材料](../outputs/interference_repair_diagnostics_20261110/literature/)。网页中公式存在HTML文本重复，不按字符结果复现算法。

| 工作与实际阅读范围 | 方法的具体机制 | 与本项目候选方向的关系 |
|---|---|---|
| [ReEvo，2402.01145](https://arxiv.org/html/2402.01145)，§3元目标、§4完整演化流程，另核对DPP算子设计段 | 个体为启发式代码；生成器与反思器分工。比较父代适应度后短期反思、交叉，再以长期反思指导精英变异。元目标为问题实例集上的算法表现；DPP分步生成交叉/变异算子，其他部分固定。 | 离线生成算子、评价后反思均已有。可借用生成框架；需要新增任务相关的证据接口、修复机制和受控证据，不能仅换成UAV地图。离线生成与在线调度要独立归因。 |
| [EoH，2401.02051](https://arxiv.org/html/2401.02051)，§3.1–3.4 | 联合维护自然语言thought、规定函数签名的Python代码与适应度；每代用E1/E2探索、M1/M2/M3修改产生候选，在实例集运行评价，再保留较好个体。 | “让LLM先写思路再写算法并筛选”本身不新；在线bin packing是其应用之一，也不能笼统称该工作只研究静态问题。我们的在线证据状态和预算内修复过程仍待实现和验证。 |

| [IGV-RRT，2603.21887](https://arxiv.org/html/2603.21887)，§II-A/B/C及§III-A的时间错位设定 | 3D场景图与ConceptNet构造GMM先验IGM；离线LLM构造多粒度语义问题，在线BLIP-2更新带置信度的分数图；联合距离、先验熵和在线语义效用，并压制已探索区域。维护局部树、root-rewiring与全局图，还有脱困机制。 | **已处理陈旧先验、在线证据和变化环境**，不能用“动态+部分观测+模型引导”概括区别。任务是目标物体搜索；候选差异在于点功率证据下的固定任务目标/总搜索预算、剩余路线修复过程组合，而非宣称我们首先考虑不确定性。当前代码也没有该文的持久树能力。 |
| [Trajectory Adaptation using Large Language Models，2504.12755](https://arxiv.org/html/2504.12755)，§3.1/3.2、§4.2反馈与§5局限 | 输入既有航点/速度、已定位的对象和自然语言修改要求；LLM产生高层计划及修改轨迹的代码。用户审核高层计划，给反馈后修订；代码可修改航点/速度。局限段承认缺少一般数学保证。 | LLM代码修改既有轨迹、闭环反馈都有先例。可研究的不同点是机器计算的可行性/固定J/资源反馈驱动有限修复过程，而不是用户偏好修改。但“反馈换成求解器”也不自动构成充分创新，仍要证明任务相关机制与收益。 |

本轮诊断不生成新算子、不调用LLM，也未实现程序内条件搜索。候选方法需要把“证据状态→修复范围/过程/资源”的机制写清楚，并证明它超过同库的数值自适应调度。相关工作没有以同一协议实验，不进行数值排名，也不使用“首次”表述。

后续最低限度的三组归因实验为：固定调度下人工算子vs生成算子；固定库下固定流程/数值自适应vs在线LLM组合；固定总资源下单次组合vs反馈修订。若只在换目标权重、增加补测或增加搜索后改善，应将收益归到相应改变，不能全记作推理优化。
