# 当前研究路线

更新：2026-11-11。本文件是当前研究顺序的唯一入口；已实现能力见[first_version.md](first_version.md)，方法设计见[research_method_20261109.md](research_method_20261109.md)。过去尝试不作为当前待办。

## 研究问题

在已知城市几何、可用自身定位，但只能沿飞行轨迹获得带噪干扰功率点测的条件下，LLM能否利用局部估计、证据时效和数值求解反馈，改善动态航路的航程—干扰暴露—任务完成权衡？

“复杂电磁”具体指本仿真中的建筑传播损耗、有限一次反射、多源叠加以及源运动/开关；不泛指全波城市传播、设备失效或任意平台抗干扰。局部GP是提供有依据且可能出错的信息的基础，不是本研究主要创新，也不把不确定性本身当作必须使用LLM的证明。

当前流程仅为：**合成建筑与隐藏动态源 → UAV当前位置功率点测 → 局部时空GP → LLM策略提议 → 数值规划/复核 → 短段飞行与新点测。** 不预先巡测，不导入初始稀疏地图，不重建完整地图，不使用地图编码或启动训练。

## 已完成：基础信息与闭环验证

已用新的独立子agent进行两场景验证，20响应且无失败/回退，出现实际补测、绕行和后续观测触发的修订；原始响应与实际执行均保存。静态与动态积分降低，但航程均增加，动态场景暴露时长增加。结论是当前信息能支持基本绕行，稳定避强和公平优化收益仍待解决，见[本轮结果](../outputs/interference_point_agent_20261109/index.html)。数值层默认RRT*，A*可作明确标注的可选对照。

验收同时检查到达、航程、飞行干扰暴露、能量和搜索/咨询次数。仅到达不能证明绕行有效，必须同时核查实际路线变化和暴露权衡；本轮证明基本避让而非全程零暴露。模型失败后的数值恢复不算模型优化收益。少量构造/随机场景只证明基本可用性，不宣称统计优势或泛化。

若未达标，依次检查模型提议、数值执行、任务预算、估计误差和观测可辨识性，不能直接增加无来源的源方位/远场真值。任何新传感信息都须有独立获取依据和显式成本假设。旧输出、退出主线的代码/配置/依赖和歧义文档已清理，当前结果有唯一入口和集中GIF。

## 当前：第一版推理优化方法与集成验证

收敛到以下两个相互配合的候选贡献。2026-11-10已实现第一版工程闭环，尚未证明新颖性或优化优势：

1. **电磁观测条件化的局部航路修复操作选择。** 用点测变化、支持/时效、不确定性、剩余路线和能量，选择要修复的航段、保留端点、搜索操作及参数；依据可以是“疑似恶化，需要绕行/补测”，不能编造真实源机制。局部修复本身不是创新。
2. **固定目标与预算下的数值反馈推理优化。** 在同一观测快照上有限轮比较候选；数值层返回可行性、代价分解、改进量和失败原因，LLM据此修订操作。统一接受器保留更好的可行候选，目标权重/约束不由LLM改变。一般LLM反馈循环本身不是创新。

已按[实际实现](route_repair_v1.md)固定J和每决策总资源台账，最多3轮反馈；支持快捷直连、局部RRT*接回、单中间点局部侧绕及全局重搜，并允许LLM分配有至少30%全域均匀分量的采样。基础模式保留probe，新修复模式暂不接主动补测。不要用改中间点的基础验证冒充区段修复或同点多轮优化，也不要仅给RRT*改名就声称实现增量算法。

集成验证已完成：单新动态场景、三方法均到达，18真实LLM响应无错误/恢复。多轮与简单数值路线/积分相同（175.940dB·s），边评价更少，但数值对照尚弱，未出现避强优化收益。该版373项测试通过，修正后记录提议重放一致。失败机制分析已由最新阶段1诊断完成；更充分的数值自适应/提前停止对照已在阶段2执行但未显示任务优势，不扩大模型规模或添加真值信息。详见[第一版结果](route_repair_v1.md)。

## 之后：受控验证，而非扩大功能清单

2026-11-10用户进一步授权先比较直接数值与短程序/算子组合，再收敛创新方法。已实现[预设算子组合](program_comparison.md)：程序只计算普通修复提议，固定目标、数值搜索和预算不变。4个同快照配对任务和一个场景的闭环对比已完成，58真实响应无错误/恢复，参数复算与审计通过，该阶段392项测试通过。程序与直接参数效果接近，没有避强或总体效率优势；相对数值组缩短航程但增加干扰积分。不使用代码进化或任意Python执行。两种接口保留作对照；当前目标/估计支持和搜索瓶颈诊断已完成，按最新阶段2冻结评价和过程接口，不把输出形式当创新。

固定共同观测接口、估计器、任务目标和总计算预算，比较全局重规划、数值局部修复、同操作集合的数值自适应、LLM单轮和LLM多轮反馈。分开检验修复范围选择、反馈修订和保留候选的贡献；报告实际航程/暴露/完成率以及总搜索消耗、模型调用/词元/墙钟耗时。

最新论文讨论把离线算子设计与在线过程组合分开归因，候选主张和对照见[方法设计](research_method_20261109.md)。离线生成好算子不自动证明在线LLM必要；若固定算子已解释全部收益，应如实收敛为自动算法设计。当前已实现离线生成的有限过程及其阶段归因，尚未实现LLM在线组合这种新过程；不因相关工作讨论而自动启动大规模代码进化或训练。

先在开发场景冻结方法和参数，再用未用场景及多个种子验证。评估应包括估计误差、噪声与变化速度敏感性，以及静态/动态源的分层表现。不能把更高传感能力、更多求解资源或事后改权重混作模型推理收益。

本地模型迁移仅在强LLM机制得到证据后再讨论；不以旧模型模仿数据为最优标签。通信中断穿越、硬暴露容忍、等待/爬升、任意代码执行、门控、地图网络和训练均不属于当前实现阶段；若要引入，先另定问题与前提。预设算子组合的有限AST解释器是本轮明确授权的实现范围。
