# 新开发任务与目标一致性检查

更新：2026-11-11。本阶段先验证开发任务是否有合法可观测风险和可改善的剩余路线，再确定是否值得离线生成算子。实验前版本单独冻结在新研究的`reports/frozen_design.md`；下列设计与后续结果分开维护。

## 实验前固定设计

使用前一阶段预留的开发seed611/613/617/619。沿用现有`generate_scenario`，地图41×31格、20m间距、6栋建筑、2–3个隐藏源、120s任务；几何连通验收与有界拒绝采样不变。不按干扰或算法效果重采样、不移动源到航路前方、不增大发射功率来展示成功。保持主配置的2.4GHz、有限一次反射/穿楼、1dB测量噪声、点测GP、飞机参数；生成器只提供建筑和源。参数为未标定研究设置。

验证seed701/709、测试seed1601/1607/1609/1613/1619/1621本阶段均不生成、不读取。当前generator源码与合并规则随协议冻结；后续若修改分布，必须重新声明开发/验证/测试版本。本轮只有4个开发场景，不足以证明统计优势或泛化。

由阶段2原`library_numeric`控制器完成4项真实闭环，固定GP、固定J、原预算均不变，无LLM。每场景捕获首次有可行剩余路线且不早于10/20/30s的实际决策，以及首次剩余路线当前干扰惩罚>0的决策。多个标签同一决策只保留一个快照；找不到标签要明确记缺失，不换场景或补造风险数组。测量只来自当前真实飞机的位置，飞行从起点开始，没有预飞稀疏地图。

每个快照使用上一阶段同样的固定几何池（区段、左右、0.5/1/1.5/2倍GP支持尺度侧移和并行绕行）。保存碰撞、超能量及可行候选；无新观测、不运行候选世界。候选池总构造/评分工作是离线覆盖诊断，不冒充一次在线预算或未来方法。

## 预声明三种评分

三者沿同一个最近邻GP栅格精确积分，长度与不确定性权重完全相同，均不读取真实源或未来。对无支持区域仍使用公开声明的内部背景先验−100dBm/std15dB，但对LLM的均值仍为null，不能当作观测到低干扰。

1. `current_j`：当前固定`长度 + 2∫clip((μ-reference)/10,0,4)ds + 0.4∫clip(σ/15,0,2)ds`。
2. `gaussian_expected_j`：只把干扰项换为`E[clip((X-reference)/10,0,4)]`，其中`X∼N(μ,σ²)`。正部期望为`E[(X-a)+]=(μ-a)Φ((μ-a)/σ)+σφ((μ-a)/σ)`；两个阈值a=reference及reference+40的正部期望之差除10，得到截断超参考期望。σ=0取确定性极限。数学公式不等于GP已校准，也不是物理功率域的期望暴露。
3. `one_std_envelope_j`：只把干扰项换为`clip((μ+σ-reference)/10,0,4)`。倍数1在结果前固定，不搜索最有利倍数。它是启发式保守评分，不声称概率覆盖、安全保证或解决未观测场。

每种评分在相同几何/能量可行、长度≤原路线1.25倍的池内选择最低分；同分保留原路线。评分与选择全部保存冻结，再调用真值评价器，按各路线到达时刻计算未来超参考秒数/积分。额外给出真实当前场冻结积分以区分时间变化影响。真实未来最小暴露候选只作橙色事后参考，不用于捕获、评分或后续LLM输入。

备选评分**仅用于离线排序诊断，不接入控制器或新接受器**。因此4个GIF只能显示原控制器，不可称期望评分或保守评分的闭环收益；不把这一步当作LLM推理优化创新。

## 开发机会门槛

预声明要求至少2/4场景存在一个捕获状态，同时满足：当前剩余路线有基于点测GP的非零干扰代价；候选几何/能量可行且长度≤原路线1.25倍；当前J比原路线至少降低1%；事后真实未来积分至少降低10%。这只是“确有同时可改善的开发机会”检查，不是在线选择能力或方法优越性证明。

报告所有场景/快照/候选，不删未达标数据。如果门槛未通过，应区分未观测到强干扰、空间估计/目标缺乏区分力、或可行修复受限；不反复筛seed直到达标，也不开始大量生成算子来弥补没有可辨识信息的状态。

评分比较分开展示：相同状态/相同池的未来积分、长度、未知占比；以及原控制器的实际闭环到达/航程/暴露。状态之间有关联、未来路线可能重叠，均值不能当作独立统计试验或将任务难度降低归于算法。下一步路线依赖实际证据：若现有信息/共同目标确能支持修复，再小预算离线生成；若不支持，先明确相应限制与可计算目标/有成本补测等方案的共同版本。

入口：`tools/run_task_readiness.py`。新研究目录拒绝覆盖，GIF集中`replay/`，运行前冻结设计/源码，场景、点测、候选、选择、事后评价分别留证。当前阶段不启动训练/RL、自由在线代码、源测向、持久树或补测动作。

三种预声明评分在全部13个状态选择了**完全相同的候选**；固定路线未来积分等权均值均为31.843dB·s，2个状态相对原路线降低至少10%，1个状态变差（超过max(0.1dB·s,原积分1%)）。状态相关且未来路线重叠，这不是13个独立任务、备选评分的闭环表现或统计检验。两个简单不确定性变换没有在本轮改变决策，不能据此否定所有不确定性方法。

一个清楚的机制例子：dev617在25.5s收到−78.81dBm点测，剩余路线当前GP干扰惩罚仅0.539、支持比例约14%。原路线固定路线未来积分103.416dB·s，池内事后低暴露参考为23.678dB·s，但它的当前J高出119.745，接受器会拒绝。35s状态也存在72.855→39.779dB·s的事后参考，而J增加107.686。它们不能给LLM作在线标签；只说明现有估计/目标下，增加搜索不必然奖励降低真实暴露的绕行。有限池没有候选不证明全空间无解，也不能唯一归因于GP、权重或传播动态中的某一项。

4个GIF均为**未更改的library_numeric控制器真实闭环**；评分和橙色事后参考仅在候选图中比较，没有执行。原传播、GP、修复接受器、RRT*与仿真源码相对阶段2保持原样；运行源码与候选清单哈希审计另存；与阶段2共有的25个核心源码文件哈希全部相同，见`reports/source_continuity.json`。不把此前真实agent的基础绕行能力或本轮基线到达当作新方法优化收益。

## 对下一步的约束

本轮没有开始离线LLM生成。继续在固定J下扩大算子生成，首先仍会遇到低暴露路线不被接受的问题，因此下一步先冻结**共同决策目标v2的设计**，再做数值可用性检查，最后才进入小预算生成：

1. 区分“已有证据足以修复”与“证据不足需要获取新点测”。风险评价聚焦即将执行的短段，并显式报告后续路线的未知；不能把长未知尾段的背景均值当作未来安全。考察在共同航程/能量约束内如何表达暴露与绕行权衡，不按事后最好路线倒推权重。
2. 若引入补测，沿用已有传感能力，只能真实飞到候选位置后得到新点测；往返航程、时间、暴露及搜索均计入共同台账。比较共同允许补测的数值规则与LLM，不能将新增动作集收益算作模型推理收益。**这仍是下一版本设计，当前修复模式没有接入补测。**
3. 用开发集冻结共同目标、动作成本、数值基线及通过条件，再做有限生成与在线过程组合。验证/测试种子继续封存。若新数值方法已解释全部收益，就只报告该贡献；不能预设LLM一定更优。

以上不是已经实现的新控制器，也不为通过门槛重采样当前城市。当前完成的是可复核的目标/信息诊断，而非论文方法收益证明。
