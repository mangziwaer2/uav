# 共享工具修复规则 v2（2026-11-20）

依据[全流程审查](reviews/20261120_llm_decision_audit/README.md)，本轮只修复F02–F08并做合成组件回归。用户“继续”授权实施，不是新的飞行实验合同，不命名为M8。不读取开发状态拟合输入、评价真值或封存数据；不调用实验决策LLM、不飞行、不点测、不训练，不重开C1/D1/M0–M7预算。原结果、GIF、冻结源码和接受标签不变。

## 修改前冻结的行为与资源约定

- F02：warm基元作为候选而非必占槽位。相同已预留求解/残差总预算内安排冷字典或替换机会，保留已找到的较优合法拟合；禁止额外免费求解。N与LLM使用同一工具规则。
- F03：不可行旧路线保留原因，仍检查共同几何候选；找不到可行路线时给明确受控失败，不能在替代搜索前断言旧路线必须可行。
- F04：分腿路径搜索须保护后腿机会与最终验证，取消不随实际需要变化的744边固定锁定；保留已求得路线。采样/边总上限不增，预算不足有具体状态，不宣称有限搜索失败等于无解。
- F05：新几何工具默认`best_feasible_v2`。只返回原预算内已实际评价、有限、满足原边界及圆域/半域、且严格改善目标的最佳候选；即使求解未收敛也可保留。单独报告求解成功/终止原因与候选合法性，不声称最优。保留显式`converged_v1`兼容政策；旧实验用冻结源码复核，不用新版本重写历史。目标/梯度各最多40次、核项最多5000，仍由原GeometrySettings进一步限制。拟合历史/GP软点不成为出生后新证据。
- F06：捷径耗尽时保留已认证前缀拼接原始尾段，raw与部分捷径仍各自经共同整路目标和硬约束复核；几何变短不直接承诺功率改善。
- F07：支持定义改为“冻结训练前缀中，至少一个点在查询时未过期且在支持半径内，查询位置可飞”。融合的距离/年龄共同来自同一个合法支持点，不让过期近点遮蔽新点；GP方差仍未校准，不称安全证书。旧D1最近点语义仅属于原合同。
- F08：JSON回执原子发布且禁止覆盖；消费方在原派发截止内重试暂不完整JSON，绑定/时钟等真实错误仍拒绝，原60秒派发/180秒回复上限不增加。

## 验证与完成边界

使用审查报告中明示的人工地图、点列、模型和人工时钟，增加行为性质回归及必要失败边界测试。只执行组件/全量CPU测试和文件完整性检查；不运行任何prepare/run/finalize科学入口。合成测试数量由覆盖上述性质决定，不通过扩大科学运行预算验证。完整性检查继续报告21个既有时序原件缺失。

本轮完成后仍需按[唯一实施顺序](current_roadmap.md)补齐任务上下文和无功率延续源池的统一LLM接口，然后另冻有限反馈与强数值组织的实验合同。工具修复、接受率或组件拟合改善不能作为LLM任务收益。
