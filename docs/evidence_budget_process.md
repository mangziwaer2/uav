# 证据条件化的绕行额度分配过程

更新：2026-11-11。本轮承接共同目标v2的开发失败分析：未知惩罚可能诱发弱证据阶段绕行，提前消耗机动余量。先做**人工数值过程与有限消融**，不调用LLM或生成新算子。实验前设计、源码、输入冻结，结果另行补充。已观察过的dev611/613/617/619仅用于开发，不称未见验证；验证/测试种子继续不生成、不读取。

## 共同部分保持不变

保持原场景、传播、传感、GP、触发周期及700样本RRT*候选生成器，采用v2同一几何侧绕池、10s风险R10、未知系数10dB、风险容差1dB·s、全程1.25D0航程上限与能量约束。每决策2100样本/10000边上限，不扩大动作集，不主动probe。已支持期望超参考暴露E与未知代价U分别记录，R10=E+U。二者都是当前GP的代理，非真实未来或安全概率。

新模块以组合方式调用原`ObjectiveOptimizer('pool_j')`生成候选；保留它已消耗的搜索/评分/终检工作，再对新选中路线做独立终检并计入同一上限，四组均采用这个包装。若终检额度不足，只能保留已经复核的旧J路线，单列资源回退。不会给恢复发新预算。原v2代码和冻结研究不修改。因选中路线/决策数不同，实际边数和总资源可以不同，不冒充等CPU。

## 过程的状态、动作与反馈

状态只读：当前时间、已经收到的带时间戳点测、软参考值、候选的当前J/长度/已支持期望暴露E/未知秒数，以及已经飞过距离、固定任务航程上限。不读取完整真值或源位置；点测升高不能解释为已知源运动或方位。

**风险证据条件**：过去10s的公开点测摘要或当前最新点测中，存在功率严格高于−80dBm软参考的读数，才启用风险侧绕选择。10s沿用原决策周期；此条件不是噪声显著性检验，单次带噪越参考可触发，保留10s历史不证明干扰仍存在。未来时间戳/非有限读数必须拒绝。无证据时按共同池旧J选路，避免仅因未知秒数少而选择v2侧绕；这不是宣称未知区域安全。

**剩余额度条件**：在已经几何、能量、全程航程可行的共同池中，最短剩余长度为Lmin（有限池参考，不是最短路径真值），已飞距离F、固定上限C，则机动余量S=max(0,C−F−Lmin)。有风险证据时，新增侧绕候选最多使用S的一半，即剩余长度≤Lmin+0.5S；不累乘全程上限。对半分配是预声明的研究规则，不声称最优或保证未来可行。旧J基线路线始终可保留，若它本身超出该局部参考额度，显式标注保留例外，不能把局部额度当新硬安全约束。

**支持风险条件**：除旧J基线外，候选的已支持期望暴露E不得高于基线E+1dB·s；若长度比旧J基线更长，则E必须至少降低1dB·s，才允许额外绕行。1dB·s沿用v2数值容差，没有根据新结果搜索阈值。该条件仍可能通过改变支持范围而误判，不是新测量、可靠信息增益或真实风险单调保证。未知秒数保持单独展示，未知代价不能单独购买额外绕行。

在通过上述条件的候选中，仍按原v2 R10最小值+1dB·s窗口取最短路线；接受条件由研究者固定，LLM不能更改。本轮过程选择的是预设几何/RRT候选，不生成新算子、不在线执行自由代码。

## 四组与归因

| 方法 | 选路规则 |
|---|---|
| pool_j | 共同池按旧J最小化 |
| immediate_v2 | 全部共同可行候选按原R10选择 |
| evidence_only | 无风险证据选旧J；有证据按原R10，无新增额度/支持条件 |
| evidence_budget | 再加入对半额度与支持风险条件 |

evidence_only用于分离证据启用条件的效果；evidence_budget相对它比较的是“额度+支持风险条件”的组合，**本轮不单独识别对半比例和支持风险条件各自贡献**。四组在同一状态下候选生成器相同，闭环后观测不同，不能声称全程同池。

## 运行、指标和预声明门槛

原样复制4个已用开发城市，运行四组共16个真实闭环。为缩短CPU运行时间允许4个独立进程并行，明确记录，不用本轮并行墙钟宣称部署时延。全部结果保存后冻结清单，再做衍生真值评价；仿真器执行积分始终不参与策略。

同时报告真实飞行积分、航程、到达、决策/边数/样本/字段计算和搜索开销；沿用上轮事后额外复算决策悬停积分。悬停不补测，真实计算不推进仿真；不声称完整实机暴露保证。GIF均为真实闭环，集中replay。

本轮开发通过条件预先固定：16项全部到达、资源/全程上限有效；evidence_budget合计飞行积分≤pool_j的90%，平均航程≤pool_j的125%；每场景暴露不得比pool_j增加超过max(1dB·s,其积分10%)。另检查基线零暴露场景的航程≤pool_j的105%，避免用无风险绕远掩盖问题。这里的零暴露场景仅用于事后统一评价，不作为策略输入或筛场景条件。比较immediate_v2和evidence_only的所有指标，但不根据哪个最漂亮更换主方法。

若失败，保留所有结果、不扫系数/重抽种子，不将输出格式、到达或人工规则称为LLM优化。若通过，只支持数值过程在这4个开发城市可用，之后才冻结更具体的状态/算子签名和小预算生成设计；是否需要在线LLM仍待公平比较。

入口`tools/run_evidence_budget.py`，新目录`outputs/interference_evidence_budget_20261111/`；原v1/v2与旧结果不覆盖，不启动训练/RL/补测/源定位。

## 拒绝分解与解释

`reports/rejection_diagnostics.json`仅对冻结状态拆解候选准入，不运行新闭环或读取未执行路线真值。dev617/619各4个风险证据状态，共8个；所有状态均没有非基线候选通过支持风险条件。只去掉半额度条件依旧无替代候选，因此本轮的“无变化”不能单独归因于保留一半额度，也不能说被拒候选真实更好。

[真实过程示例](../outputs/interference_evidence_budget_20261111/reports/example_process.md)：dev617在25.5s尚有210.238m机动余量，基线路线480.952m；某侧绕560.952m，符合586.071m的局部长度限。其R10从53.200降到37.738，但已支持积分E从9.091升到14.221dB·s，于是被拒绝。支持时长也从5.589增到7.648s，说明E积分覆盖范围变了；用E必须单调改善作为必要条件，不能保证是在公平比较全部近期暴露。

这些结果否定的是本轮具体人工条件，不证明任意证据调度都无效、不证明缺少新传感器，也不推翻此前强agent能够基本绕行的结果。“只有越参考后才侧绕”没有显示优势，当前实验也不能单独识别触发时机、路径形态和后续观测各自造成多少变化。

## 后续收敛

本过程保留为负面对照，不升为默认方法，不继续在这4个城市扫描半额度比例、越参考阈值或未知系数。下一步先冻结**最小离线过程接口与评价合同**：

- 真正硬约束为当前几何/端点、能量、固定全程航程上限及共享搜索资源；支持积分E、未知秒数、R10、点测趋势与证据时效作为可分解的诊断量，不能再把“E必须改善”冒充真实风险保证。
- 过程可以在预设算子/候选中决定保留、侧绕或修复，并选择使用多少机动余量；受限解释器不执行任意Python。修改准入或接受规则必须另立共同版本，让数值对照和后续LLM都使用，不能给LLM特权。
- 先固定任务级评价和小预算开发协议，再有限生成；评价器可给离线设计反馈，但隐藏源、未来脚本、未执行路线真值不能进入运行时状态。既要保留强数值对照，也要有未见场景验证，不能把开发拟合当论文优势。

这是下一阶段设计任务，当前没有新接口实现、离线生成调用或在线LLM过程。主动补测仍是另立有成本版本的可选方向，不因本轮失败直接增加感知能力。

本轮共记录123个真实决策。收尾证据核验脚本`reports/verify_evidence.py`另行复核27个共有核心模块的哈希、4场景四组初态池与搜索评分工作、旧两组8项轨迹指标重现、从真实已收到点测重建123个选路风险，以及16GIF的episode/文件哈希与全帧解码。运行完成的核验结果以`reports/evidence_verification.json`为准，不以脚本存在冒充通过。

上述接口任务现由[离线过程合同](offline_process_contract.md)实现并通过24项同状态工程核验；仍无生成模型调用或新飞行。此处实验前设计与当时结果保持原样，当前执行顺序以current_roadmap为准。
