# C一致搜索原语：前瞻开发协议

2026-11-11。用户授权继续迭代算子结构；本轮先验证搜索目标错位，不追加旧实验预算。

## 结构与信息

研究者编写`PowerTimeSearchObjective`，RRT*选父、重连、后代代价更新和终点连接统一使用
`C_edge = ∫[1 + λ E(10^((P_dBm−P0)/10))] ds/v`，单位秒。λ=1、P0=−80dBm、背景−100dBm/先验标准差15dB与原v3完全相同。支持区使用当前GP均值/标准差的对数正态期望；未知区只用声明先验，不读取未知数值栅格。这不是抵达时场预测、实测校准或安全上界。

新模块`src/uav_em/aligned_search.py`独立接入原RRT*，不改旧模式、GP、传播、共同C接受器或观测。共同候选池仍按旧J构造；本轮只改变池后的一个搜索原语，不能称整个系统所有搜索均已对齐。

两组使用相同空搜索缓存，与接受器的J诊断缓存分开；共享2100采样/10000边总账，含已付共同池与终检。C额外构建功率栅格，记录节点数和墙钟；等边数不等于等CPU。随机种子由场景/当前时刻/profile/当前路线/搜索目的决定，不含目标名称或累计调用数。最终仍按同一C从全部可行候选选择，不因新搜索强制换路。

## 冻结预算与顺序

1. 复用因果反馈研究的四个dev617状态（20、25.5、35.5、45.5s）和原共同池/已付资源，不使用扩大诊断池。两目标old_J/power_time_C × 两操作local_pad1/global_focus，共16同状态求解，每项只增加一次最多700样本搜索。四任务相关，不作统计泛化。local_pad1是预声明主参考，global_focus只作敏感性，不能根据真值选闭环策略。
2. 复用原v3的dev611/613/617/619配置，两个控制器均固定local_pad1、同池/接受器/总预算，共8真实闭环飞行，不补场景、不选seed、不重试失败。固定全程1.25D0上限及能量约束不变。
3. 求解前冻结协议、源码及输入。16项候选/选择全部冻结后才作未来真值派生评价；8飞行按当前真值产生实际噪声点测，全部运行冻结后才作派生评价。所有失败保留。验证701/709及测试种子继续封存。
4. 0模型调用、0新离线生成提交。新结构为研究者编写，不记作LLM生成/选择收益。下一轮离线生成需另冻合同与小预算。

## 指标与结论边界

报告每状态当前C、固定路线未来T+Q/超参考积分、航程和资源；闭环报告到达、航程/能量、真实连续功率、T+Q、超参考、前50m进度、实际采样/边/墙钟。补计固定决策悬停的T+Q，与飞行指标分开。GIF为8次实际闭环，集中replay；左图真值仅供事后查看。

同场景成对比较且保留反例。主描述量为四场景总真实T+Q是否下降，并报告每场景暴露/航程退步，不声称显著性、稳定避强或模型必要。即使当前C下降，也可能因有限点测/未知先验或时变GP代理偏差而使真实暴露增加。结构迭代不能自动修复信息不可辨识。
