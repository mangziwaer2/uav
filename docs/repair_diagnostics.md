## 结论及其依据

当前主要障碍不只是搜索范围。**在这4个开发快照中，更低的当前GP代价不可靠地对应更低的未来真实暴露。** 有限候选池里都有实质减暴露、却不符合当前J接受条件的路线；继续扩大RRT搜索或把参数改成代码输出，不能直接消除这种目标/估计与任务指标的偏差。

候选池共314条记录，其中256条满足几何/当前能量条件；不隐去碰撞、无解和超能量候选。包含72次独立搜索，累计36,390个样本、625,429次边评价，另有几何池评分开销。每次搜索单轮请求700样本，在2100样本/10000边上限内运行，可能先耗尽边预算；不是把全部离线搜索算作一次同预算方法。

快照沿用上次预声明的4个选择点，没有看本轮结果换场景。所有候选只用公共几何、当前GP和已发生点测生成，保存并SHA256冻结后才实例化真值世界。事后按原传播公式，用每条路线各自的到达时刻积分，不把未来源脚本反馈给生成器。

以下比较的是从快照出发、**不再补测或重规划的固定路线反事实**，不是完整飞行策略。长度上限为原剩余路线1.25倍、积分降低至少10%是预声明的诊断阈值，不是硬件安全线，也没有加入在线控制器。

前两个最低J与原路线同分，仅有浮点/共线分段差异，当前严格改进接受器不会因此换路。其很小的积分差异属于积分离散差异，不能解释成优化收益。图中橙色路线按事后未来真值选择，**没有可在线使用的选择依据，不是LLM已经能选出的路线**。表中大幅降幅只说明有限池中有这种权衡机会，不能宣布方法取得相应提升。

最直接的例子是s02早期：当前路线500.85m，J=690.387；快捷连接466.41m，J=641.622，但未来积分53.798→116.716。两条路线在当前GP上的干扰惩罚都为零，改进主要来自长度和不确定性路程减少。565.63m的侧绕参考未来积分仅1.894，却有J=780.930，按当前接受器必须拒绝。即使模型猜中这条侧绕，它也不能通过当前固定接受条件；不能把遵守固定J与“已经优化真实暴露”混为一谈。

## 搜索、估计与时变分别看到什么

- **搜索覆盖：** 仅s02早期的几何快捷连接比这18次独立RRT返回的最佳J更低；这个快捷连接在上次试验已经被数值组和两个LLM组发现。其余3个快照未在本池观察到额外J覆盖缺口，不能推出搜索最优或继续搜索无用。
- **信息支持：** 原剩余路线当前支持比例仅15.1%–33.5%。在仍有支持的位置，GP相对当前真实场的沿路加权MAE为7.55–11.89dB；这是四条路线上的描述性误差，不是全图精度、标准差校准或传感器误差。
- **未知路段：** s02早期原路线的未来超参考积分全部发生在决策时未支持的位置；快捷连接约97.1%也在那里。规划器并没有低干扰证据，只是用背景均值与未知标准差计算当前代价。
- **场随到达时间变化：** s01早期原路线按当前真实场冻结积分为84.090，到达时场积分为173.864；s02早期则63.866→53.798。空间估计偏差和随时间变化均可影响排序，不能从这些数值唯一推断源位置/运动，也不能把全部差异只归到某一种机制。
- **目标权衡：** 四个快照中，满足长度参考且降低至少10%未来积分的27条候选全部不改善原路线当前J。这里包含估计不足、未知代价和长度权重的共同作用；诊断没有独立消融出每项的因果贡献。

这些证据不证明点测能力本身不够，也不证明LLM不可能改善任务；它们说明当前实现/参数/四个状态下的限制。没有修改GP、增添免费测向、调整源或事后改权重。

## 最小算子合同草案：下一阶段实现范围

现有库是参数生成函数，尚非以下完整过程解释器。先把状态与反馈合同冻结，再做人工算子/数值流程基线；之后才离线生成和在线组合。下面是设计草案，不能列为已实现能力。

| 接口层 | 最小输入/输出 | 必须遵守的边界 |
|---|---|---|
| `RepairState` | 快照时间、剩余路线版本/anchors、逐段J分解、支持比例/年龄/不确定性、近期点测、已知几何、剩余能量和资源 | 不含已飞路线的可修改ID；未知均值为null；历史点测不是未来源证据。数值算子与LLM可见字段必须逐项声明，不能暗中增加传感信息。 |
| `select_interval(state, metric, padding)` | 输出当前版本的起止anchor ID与选段依据 | 区分已支持干扰、未知前沿、证据陈旧和几何冗余。没有支持的区域不能因均值先验低就称安全；全零干扰排序需显式报告无区分力。 |
| `construct_corridor(state, interval, side, scale)` | 输出候选搜索区域/中间点与几何检查结果 | 左右只是几何候选，不是源方位。先检查碰撞/地图边界，记录无效构造；允许扩区间，禁止改起终点。 |
| `allocate(state, feedback, work_left)` | 输出本轮样本额度和分区权重 | 统一台账，跨顺序步骤/双腿/反馈共享；保留全域探索。不能只约束单次搜索后无限加轮。 |
| `search(interval, corridor, allocation)` | RRT*输出完整候选或失败、实际采样分布、边耗用和首解信息 | 原候选与接受后的路线分别留存。碰撞、预算耗尽、有解无J改进应分开，不让“无J改进”冒充“没有低暴露路线”。 |
| `assess(candidate, state)` | 固定目标分解、长度/能量、支持/时效分布、与已有路线差异 | 统一接受器不由LLM修改。未来真实暴露只进入离线评价，不进入本反馈。支持不足是可计算的证据条件，不是必然危险/安全标签。 |
| `process(steps, bounded_conditions)` | 有限顺序与条件：局部失败→扩区间；无区分力→换构造或停止；预算不足→保留 | 这是未来要扩展的过程组合，不是当前12条赋值解释器已支持。只允许预设有限分支/步数，禁止自由Python与任意循环；条件阈值先冻结。 |

反馈最少保存：请求/快照/路线版本、操作ID、有效候选ID、接受/拒绝原因、J四项分解、支持/未知段占比、样本/边消耗、剩余额度、同快照是否有新信息，以及`no_inference_of_true_source`。数值反馈不能包含本轮事后参考路线或其真值评分。

## 下一阶段的研究决策

先冻结任务评价合同，明确“更好”指固定估计J的求解改进，还是实际干扰—航程权衡。**当前J下降不能作为避强能力的替代指标。** 如果继续保持当前J，那么生成算子首先只主张改善求解质量/资源，闭环暴露需独立验收，不能承诺本轮事后参考的收益。

如要改为更贴近动态暴露的目标，应另立新的共同目标与开发/测试集，用现有点测/时效/不确定性推导可计算评分，再让所有方法使用同一版本。不能为LLM单独放宽接受、以未来真值筛路线或为展示绕行临时改权重。本轮不实施这类改动。

若研究涉及补测，需要显式加入航行/时间/能量成本及实际新点测，再比较相同补测权限的数值对照；新修复模式尚未接此能力。不要仅用更强的搜索去补一个没有新信息的状态。哪一种路线值得发展，要由下一阶段受控试验决定，而非从事后橙色路线推回一个“正确”在线策略。

建议下一阶段先落`RepairState/Feedback`、候选去重与有限失败分流、强数值自适应基线，使用当前J形成求解诊断的可复现下限；任务指标与目标一致性单独设立通过条件。只有在这些基线和评价明确后，才进行小预算离线LLM生成与互补算子保留，再做同库在线组合/反馈归因。相关方法差异见[全文方法段比较](related_methods.md)。
