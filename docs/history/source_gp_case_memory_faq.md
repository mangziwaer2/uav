# 源假设、GP、历史案例与“同色图仍绕行”

最新设计更新：用户提出应同时使用GP，此建议已纳入[GP＋等效场与前方路线影响触发](../gp_equivalent_trigger_design.md)。本文关于当前代码/旧缓存的事实不变；下文“本轮不加入融合”是此前研究范围，不再作为下一步限制。融合尚未实现，案例库仍是可选。

2026-11-19。本轮是代码/保留缓存核对及文献阅读，没有新拟合、GP查询、场真值查询、路线评分、LLM决策或飞行。缓存中的既有路线评分与显示数组范围见[核对记录](../references/case_memory_20261119/cached_route_explanation.json)。以下区分当前实现与可选设计，不启动数据采集或检索系统。

## 现在的源假设怎么生成

输入是UAV已经得到的`位置、时间、总功率`序列，不是GP预测的地图，也没有在候选源位置实际测量。

1. **在UAV附近列候选团。** `operator_dictionary`在当前位置160m圆域内列80m间隔的候选中心，边界超出城市则不列；可用相对goal方向的左半域、右半域或完整任务圆域。不是全地图随机撒点。每个中心配40/80/160m尺度；静止、四个轴向3m/s平移、±0.5dB/s强度变化来自有限机制字典。
2. **算候选团对历史接收点的响应。** 对每个候选，计算它在历史各时刻的位置，以及在各历史UAV位置应产生怎样的衰减形状。若是假设源在A，比较的是“源在A时，UAV过去经过那些点会读到什么”，不是“测量A处的真实功率”。当前形状是径向高斯代理，不是仿真中的反射/穿楼传播模型。
3. **贪心选基元。** 取最近最多12条历史读数，先按候选形状与当前拟合残差的相关性挑选候选，而非为地图每个点各运行一次完整拟合。
4. **调整强度，必要时再加一个基元。** 有预算的最小二乘连续调整所选基元的幅度；最多两个基元，功率在线性单位下叠加背景与基元，再转dBm比较历史读数。加第二个基元后联合重估强度，不是把两个分别拟合最好的单源直接并在一起。旧同机制模型可平移到当前时刻作热启动，具体流程有这一例外。
5. **保留不同机制/区域的候选环境。** pilot用较早数据拟合并把最后三条已知读数作为回顾反馈；refine作业可以再利用完整已收前缀。回顾反馈不等于未见未来预测证据。当前每次事件最多3作业，得到的每个解释可含1–2个基元。
6. **新解释出生，随后接受真实新点测检验。** 现行规则把旧池质量乘0.75，将0.25均分给新解释；之后按出生后先预测、再取得的读数更新相对质量。拟合得好不直接换成高后验，LLM也不设置这些权重。

因此，用户所说“摆放可能源，再看能否解释历史读数”是对的，但当前是有限字典、贪心选形状、联合拟合强度，并没有连续优化所有源位置/速度。两个叉可属于一个双源解释；多个互斥解释不能都当成真实源同时叠加。

代码见[event_inference.py](../../src/uav_em/event_inference.py)、[event_llm_inference.py](../../src/uav_em/event_llm_inference.py)、[equivalent_field.py](../../src/uav_em/equivalent_field.py)。

## GP是否需要先提高精度

当前点测分为两条支路：一条更新局部时空GP，一条直接更新/拟合源假设池。`mixture`整路评分不含GP融合；GP用于独立`gp_numeric`参考及供路径LLM阅读的局部样本。不是“GP先补全地图，再让源拟合那张地图”。

所以，GP变准可能改善局部提示与GP参考，但不会自动修复现有mixture中的错误源解释。现在不能因为有GP就断言其已足够，也没有必要等GP完善才继续修源。要分别看实际后续点测、预测时距、空间支持及路线排序，而非仅看热图是否漂亮。

如果以后检验出“源结构有用，但局部幅度偏差大”，可以研究每个候选源趋势加一个由同批历史残差拟合的局部GP修正。它是一个联合模型的条件校正，不是把共享观测的源模型和GP当独立传感器相乘。当前尚未实现，不与本轮局部细化同时默认加入。

## LLM现在能做什么，以及建议增加什么

当前推断接口允许LLM选择`机制、许可区域、1或2基元容量`，pilot后看数值工具反馈再选refine作业。完整任务域半径仍固定，LLM不能任意缩成“肯定无源”，也不填写源参数/世界权重。保留C1中这些推断选择实际上是数值feedback，LLM只提出路径；缺失的新事件记录不能从旧GIF中替代推断。

直接指定一个区域只是预算分配，不能保证该区域真的有源。更有价值的职责是：根据旧预测哪里失配，决定值得检验的替代解释、细化哪个粗解、花多少工具计算，随后利用工具返回的残差与路线分歧继续计划。新中心/尺度局部细化仍是[下一步具体方案](hypothesis_refinement_plan.md)，尚未实现。

沿单直线的读数可能无法区分上下镜像环境。LLM可以维护两种可检验解释，但没有依据时不能凭常识选择“真实方向”。

## 历史飞行案例库：可行，先做小而明确的版本

本轮重新联网检索并下载、选读三篇全文方法段，出处/哈希与阅读范围见[来源](../references/case_memory_20261119/sources.json)、[阅读记录](../references/case_memory_20261119/reviewed_method_notes.md)。

- [ExpeL](https://arxiv.org/abs/2308.10144)，§4.1–4.3：收集经验，比较成功/失败，提取可修订经验，并在新任务检索相关轨迹。不更新LLM参数。
- [Voyager](https://arxiv.org/abs/2305.16291)，§2.2–2.3：技能库检索、反馈及执行错误用于修订程序。借鉴受检验算子及适用条件的存储，不据此恢复任意在线Python或自动无限探索。
- [Reflexion](https://arxiv.org/abs/2303.11366)，§3：把任务反馈总结为记忆，辅助后续尝试。题名中的verbal RL并不要求本项目启动参数训练或传统RL；反思文字也不是物理测量证据。

建议案例单位是**一次决策/修订事件**，而不是一整张真源地图或一句“左绕成功”。每条记录包括：

| 部分 | 内容与使用方式 |
|---|---|
| 当时可见前缀 | UAV相对goal的位置/航向、最近功率及变化、历史路径覆盖、GP支持与不确定性、已有解释及已发生残差 |
| 算子与工具反馈 | 检验了哪类机制、哪个许可区域、哪个细化作业，拟合/开发残差、失败原因及资源 |
| 冻结预测 | 这次修订对随后接收点或预定时距发出了什么预测 |
| 实际后果 | 后续实际点测、模型是否继续失配、路线是否接受/执行、飞行与暴露结果；明确记录时刻，不倒写到前缀 |
| 可复用建议 | 适用条件、应尝试的算子、可能失败条件，保留案例来源。没有配对/反事实证据时，不能把一次成功总结成因果规律 |

查询时只使用当前已见前缀，先按功率趋势、解释残差、飞行转向、支持覆盖和公开几何检索少量近似事件，再让LLM决定工具计划。历史失败案例应保留；到达goal并不说明源解释正确。不能照搬旧城市的源坐标或左/右路径，更不能把经验建议直接当新传感证据。

真实源、未来脚本和完整评价图不放入发给决策LLM的检索条目。城市及相关多方法航迹按城市整体划分，评测城不进入库；当前测试城市仍封存。若需用仿真真值做离线标签，应另冻用途和边界，并与检索公开内容分开。

可先从现存开发航迹整理少量案例验证格式和检索；现存C1仅两个已见场景，不能称覆盖丰富的经验库。当前不必为RAG新建大量飞行，更不要求GPU训练。是否扩大采集，取决于一个小预算验证是否显示检索让LLM更好地选择修订工具。

后续必须比较同LLM、同工具、同信息来源与总预算下的有/无案例检索，并保留数值调度。单纯加RAG或引入三个已有框架不算本项目独有创新；候选贡献是“与失配类型和路径相关的经验检索，改善有限预算的等效场修订及重规划”，尚未证明。

## 为什么full_mixture几乎同色，UAV仍绕行

先承认用户的推理：若未来各处一直有相同功率、同一出发时刻和速度、直线无遮挡，那么绕远只会增加航时与累计暴露，应选直线。仅有一张“当前时刻看起来全红”的图，并不满足这些条件。

保留C1的实际缓存解释如下：

| 时刻 | 当时实际发生的事 |
|---|---|
| 20秒显示帧 | 是处理前帧，旧池几乎全为延续；这张显示图在新解释出生之前。 |
| 20秒决策处理 | 重新拟合出生三个解释，总质量0.25；旧池0.75。LLM提出浅南偏，数值层按当时冻结池与未来到达时刻评分并接受。 |
| 24.5秒显示帧 | 新生解释已经接受后续点测评分，延续质量升至0.992455；当前图范围约−71.00766至−70.88297dBm，仅约0.125dB，在45dB统一色标下几乎同色。UAV仍执行20秒提交的路线。 |
| 32秒 | 下一次旧C1固定咨询，接回goal。这不是新功率上升事件策略的飞行证据。 |

20秒的**原有缓存**路线评分为：

| 路线 | 预测剩余航时T/s | 预测功率积分代理Q | 预测T+Q |
|---|---:|---:|---:|
| 直达 | 29.0000 | 224.5688 | 253.5688 |
| 经[430,270]浅绕 | 29.3708 | 222.3886 | 251.7594 |

所以当时的模型认为多飞约0.37秒可少约2.18代理秒暴露，浅绕总分更低。这只是当时预测，不证明真实收益。

这里有三个容易混淆的点：

1. **图是当前切片，路径按未来到达时刻评分。** 当前空间近似同色，不等于几秒后的各处也同色。
2. **当前权重不等于最近一次决策权重。** 点测后权重持续更新，但旧C1不每点重新选路。24.5秒的新图不是20秒提交路线的原始理由。
3. **旧回放抽帧缺少关键决策后快照。** 当前LLM双图中，20秒处理前之后直接显示24.5秒，跳过了新解释质量25%时的决策状态。不能用这两帧推导“当时完全均匀却被数值层选了绕行”。

因此，之前把实际飞行简称为“按full_mixture”不够精确，应是：**按最近一次决策时冻结的完整假设池，在未来沿途时刻评估并提交路线；当前回放图可能已更新。** 后续新回放应标明当前时刻、路线提交时刻与其冻结评分，并保存事件前后帧；不能把旧曲线改画成新飞行或用其他时刻真值充当缺失快照。
