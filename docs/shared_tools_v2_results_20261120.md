## 接受规则与实现边界

`refine_fit`与`constrained_refine_fit`默认采用`best_feasible_v2`：只保留种子基线及已实际objective评价的有限合法候选，接受仍须严格改善、满足原盒边界与任务圆域/半域。收敛与候选接受分别记录；保留`converged_v1`作为显式收敛政策，完整旧复现仍须使用旧冻结源码。基础`fit_job`也保存已评价合法最佳候选，不再把求解非收敛等同无改进。

初版修复和只读交叉复核发现、随后补齐的边界：

- 原子发布不得用会覆盖目标的replace冒充独占创建。
- 旧源中心若已细化到字典外，仍需参与可选幅度重拟合；不因开放新字典而丢掉旧几何能力。
- NaN/Inf求解诊断记为null，非有限梯度受控停止并保留合法已评价候选，避免严格JSON保存失败掩盖结果。
- 不可行候选与预算失败分开记录；最坏配额验证预留仍保守，有限搜索失败不是全局几何无解证明。

N与LLM调用同一套工具、相同上限，没有为LLM放松几何/资源接受条件。源修订仍不继承出生后证据，GP软点仍不计新传感证据。新默认会改变未来运行；活动源码已不同于M7，不能调用旧check宣称当前源码仍复现旧合同。旧冻结源、结果、GIF与接受记录保留。
